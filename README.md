# 话术微调标注工具（pair_annotator.html）

一个**单文件、零依赖**的浏览器端标注工具，用于对 LLM 多轮对话（SFT 语料）里的 `user` / `assistant` 话术做人工改写、检索与批量替换，并把结果导出成 JSON 补丁或完整文件。

整个工具只有 `pair_annotator.html` 一个文件：HTML + CSS + 原生 JavaScript 全部内联，不需要 Node/npm、不需要构建、不需要联网（除非用 `?data=` 自动加载），双击即可使用，数据全程留在本地浏览器内存中。

## 功能特性

| 能力 | 说明 |
| --- | --- |
| 结构校验 | 加载 JSON 时立即校验会话结构（system 唯一、user/assistant 严格交替、轮次成对），不合法会列出问题并拒绝加载 |
| 成对编辑 | 按「轮」渲染卡片，`user` / `assistant` 消息用自适应高度的文本框直接改写；`system` 固定只读、可折叠 |
| 原文对照 | 单条消息可展开「原文」查看修改前内容，一键「还原」回到原值 |
| 改动可视化 | 打字时实时用绿色底色标出被改动的文字区间；消息头出现「已修改」徽标，侧栏出现「改 N」计数 |
| 全局检索 | 关键词跨全部会话搜索，命中处黄色高亮、当前命中橙色并自动居中滚动；命中折叠中的 system 时会自动展开 |
| 会话筛选 | 侧栏可按「全部 / 已修改 / 未修改」筛选，也可用关键词过滤会话 |
| 批量替换 | 以当前搜索词为查找目标，跨全部会话批量替换（带预览确认、影响面统计、一层撤销） |
| 标注人署名 | 一次性填写标注人或工号，写入导出文件名，便于多人协作溯源 |
| 两种导出 | 完整文件 / 修改内容（一次点击同时导出「带记录」与「原格式」两个文件） |
| 本地暂存 | 编辑内容防抖写入 `localStorage`（当前版本未在启动时回填，详见[已知限制](#已知限制与注意事项)） |
| 大文件友好 | 侧栏一次性拼接 `innerHTML` + 事件委托，检索文本惰性构建，几万条会话也能流畅操作 |

## 快速开始

### 方式一：直接打开（最简单）

1. 双击 `pair_annotator.html`，或在浏览器中 `Ctrl+O` 打开它。
2. 点击右上角 **「打开数据文件」**，选择待标注的 `.json`（UTF-8 编码）。
3. 第一次导出时会弹窗要求填写 **标注人**（姓名/工号），填一次即可。
4. 开始改写，改完点击任一导出按钮下载结果。

> 这种方式完全离线，不依赖任何服务。

### 方式二：本地 HTTP 服务（支持 `?data=` 自动加载）

浏览器对 `file://` 下的 `fetch` 有安全限制，若想用 URL 参数直接加载数据，必须先起一个静态服务：

```bash
# 在数据与工具所在目录执行
python -m http.server 8000
```

然后访问：

```
http://localhost:8000/pair_annotator.html?data=subset_1000.json
```

`?data=` 支持相对路径/子目录（如 `?data=M2/subset_1000.json`），页面会用文件名作为导出的基础名。

## 数据格式要求

顶层必须是**会话数组**，每个会话是一个含 `messages` 的对象：

```json
[
  {
    "messages": [
      { "role": "system", "content": "你是一名专业客服，请礼貌、简洁地回复……" },
      { "role": "user", "content": "我的订单还没到，怎么查？" },
      { "role": "assistant", "content": "您好，请提供订单号，我帮您查询。" },
      { "role": "user", "content": "订单号 12345" },
      { "role": "assistant", "content": "已为您查询，预计明天送达。", "loss": 0.82 }
    ]
  }
]
```

加载时按以下规则逐条校验（校验完全在页面内完成，不依赖任何外部脚本）：

1. 顶层是 JSON 数组；
2. 每个会话含非空 `messages` 数组；
3. 每条消息含字符串型 `role` 与 `content`；
4. 首条消息必须是 `system`，且整个会话只能有这一条 `system`；
5. `system` 之后的 `user` / `assistant` 必须严格交替；
6. 非 system 消息数必须为偶数（轮次成对，不允许悬空的半轮）。

不通过时页面会弹窗提示「数据结构校验未通过，共 N 处问题」并拒绝加载（最多展示前 10 条，修正后重新加载即可）。

> `messages` 里的其他字段（如示例中的 `loss`）会被原样保留；`loss` 有值时会在消息头以灰色徽标 `loss: 0.82` 展示，仅供阅读，不参与编辑。

## 界面与操作

### 顶栏

| 元素 | 作用 |
| --- | --- |
| 标题 / 进度文字 | 显示 `文件名 · 已修改会话 x/y · 已修改消息 z` |
| **标注人：xxx** | 点击可修改署名（存于 `localStorage`，文件名会用到） |
| **打开数据文件** | 选择本地 JSON（也可用 `?data=` 自动加载） |
| **导出完整文件** | 导出应用了全部修改的整份数据 |
| **导出修改内容** | 一次导出两个文件：带记录的 payload + 原格式数组（仅含被修改会话） |
| **撤销** | 预留按钮，当前版本未绑定逻辑（批量替换处另有可用的撤销） |

### 左侧会话列表

- 每项显示：会话编号 `#i`、轮数、已修改条数徽标 `改 N`、首条 user 内容预览。
- 顶部下拉筛选：`全部` / `已修改` / `未修改`。
- 主区域搜索框输入关键词后，侧栏也会同步按关键词过滤会话（支持匹配会话编号）。
- 点击任意会话即切换，当前会话以蓝色左边框高亮。

### 主编辑区

- 顶部工具条：搜索框 + `↑` / `↓` 匹配跳转 + `x/y` 匹配计数 + 批量替换区 + `← 上一条` / `下一条 →` 会话切换。
- 标题显示 `会话 #i（共 N 轮）`，其中轮数按 `(消息数 - 1) / 2` 计算。
- `🔒 system（只读）` 卡片：默认折叠到约 5 行高，点「展开/收起」切换；内容不可编辑。
- 「第 k 轮」卡片内依次渲染本轮各条消息：
  - 消息头：角色徽标（user 蓝 / assistant 绿）、消息序号 `#mi`、可选 `loss` 徽标、「已修改」徽标、`原文`、`还原` 按钮；
  - 正文：文本框自动随内容增高；被改动的字符以绿色底标出，搜索命中以黄色底标出（重叠时搜索优先）。
- `原文` 展开后在下方显示一条虚线框的原始内容；`还原` 会把该条恢复为原始文本并清除对应修改记录。

### 快捷键

| 位置 | 按键 | 行为 |
| --- | --- | --- |
| 搜索框 | `Enter` | 跳到下一个匹配 |
| 搜索框 | `Shift + Enter` | 跳到上一个匹配 |
| 「替换为」框 | `Enter` | 触发批量替换（先弹预览） |
| 标注人弹窗 | `Enter` / `Esc` | 确定 / 取消 |
| 文本框 | `Ctrl + Z` | 浏览器原生撤销（仅当前文本框） |

## 批量替换与撤销

批量替换以**当前搜索关键词**为查找目标，作用是**整个文件的所有 user / assistant 消息**（不只是当前会话）：

1. 在搜索框输入要查找的关键词/短句（例如「亲」）。
2. 在右侧「替换为」框输入新内容（例如「您好」）。
3. 点 **批量替换**（或在替换框按 `Enter`）。
4. 弹出预览：显示「影响 N 条会话，共 M 处」并列出前 3 条 diff（旧内容红色删除线 → 新内容绿色）。
5. 点 **确认替换** 生效；点 **取消** 不做任何修改。
6. 替换后可用 **↶ 撤销上一批** 回滚这一批（只保留最近一批，执行新一批后旧的撤销点即被覆盖）。

注意点：

- **区分大小写**：批量替换按字面量精确匹配（`split`/`join`），而搜索高亮忽略大小写，两者行为略有差异。
- 同一消息内的**所有**匹配都会被替换。
- **不允许替换为空字符串**（想删除关键词请手动编辑）。
- `system` 消息永不参与批量替换。
- 替换后的内容如果恰好等于原文，该消息会从修改记录中移除（不算「已修改」）。

## 导出文件

两个导出按钮在未填写标注人时都会先弹窗要求填写，填写后自动继续导出。

### 1. 导出完整文件

把全部会话的修改应用后整份导出，结构与原文件完全一致，可直接进入后续训练/处理流程，不需要再合并。

```text
full_<原文件名去掉.json>_<标注人>_<YYYYMMDD_HHmmss>.json
```

### 2. 导出修改内容

只导出**被修改过的会话**（整条会话的完整数据，其中 content 已替换为改后文本），一次点击会依次下载两个文件（间隔 500ms，带记录版在前）：

**① 带记录版（审计用）**：`patch_audit_<base>_<标注人>_<时间戳>.json`

```json
{
  "source": "subset_1000.json",
  "data_sig": "1000:5001:312:248",
  "annotator": "张三",
  "exported_at": "2026-10-23T02:15:33.120Z",
  "edit_count": 12,
  "conversations": [ /* 被修改的会话，结构与原文件一致 */ ]
}
```

- `source`：来源文件名；
- `data_sig`：数据指纹 `会话数:消息总数:首条 system 字符数:最后一条消息字符数`，用于校验补丁与原始文件是否同一份；
- `edit_count`：**会话条数**（不是消息条数）。

**② 原格式版（直接可用）**：`patch_raw_<base>_<标注人>_<时间戳>.json`

与上面相同的会话集合，但直接输出为 JSON 数组，不包装任何元信息，结构与原文件完全一致。

若当前没有任何修改，会提示「当前没有修改内容可以导出」，不会生成空文件。浏览器若拦截「下载多个文件」，需在地址栏右侧允许本站点多次下载，否则只会保存第一个文件。

## 本地暂存

- 每次编辑后延迟 300ms 防抖写入 `localStorage`，键为：

  ```text
  pair_annotator:<文件名>:<会话数>:<消息总数>
  ```

  这样同名但内容不同的文件不会互相覆盖暂存。

- 标注人单独存在 `pair_annotator_annotator`，做过去噪处理（`\ / : * ? " < > |` 与空白替换为 `_`）。
- **加载文件时会清空该文件对应的暂存**，且页面刷新后不会自动还原编辑（代码中的 `restoreEdits()` 目前未被调用）。因此**请及时导出**，不要把浏览器当作长期存储。

## 仓库结构与产物用途

```text
llm-sft-pair-annotator/
├── pair_annotator.html   # 标注工具本体（单文件，唯一运行物）
└── README.md             # 本文件
```

工具不依赖任何后端或脚本，导出物的用途如下：

| 导出物 | 内容 | 典型用法 |
| --- | --- | --- |
| `full_<base>_<标注人>_<时间戳>.json` | 全部会话，已应用所有修改 | 直接作为训练数据，不需要额外合并步骤 |
| `patch_raw_<base>_<标注人>_<时间戳>.json` | 仅被修改的会话（原格式数组） | 只回填改动过的会话，减少数据搬运 |
| `patch_audit_<base>_<标注人>_<时间戳>.json` | 同上的集合 + `source` / `data_sig` / `annotator` / `exported_at` / `edit_count` | 归档审计、多人成果核对与溯源 |

注意事项：

- 两个 `patch_*` 文件只包含**被修改过的会话**，未改动的会话不在其中。
- 数组**不记录会话下标**，顺序是「首次改动的先后顺序」，因此按会话回填时需要自己用内容（例如首条 `system` + 首条 `user`）去原文件里定位；想省掉这步就直接用 `full_*` 完整文件。
- 多人标注同一份数据时，用 `data_sig` 确认大家基于同一份原始文件，再按 `annotator` / `exported_at` 核对同一会话的多次改动并人工裁定。

## 实现要点

- **单文件、无依赖**：样式、DOM 结构、逻辑全部内联在 `pair_annotator.html`，没有框架、构建步骤或第三方库。
- **编辑以 diff 存储**：`state.edits` 是一个 `Map`，键为 `"会话下标:消息下标"`，只保存与原内容不同的文本；导出时才把 diff 应用到数据副本上，因此「还原」只需删除键。
- **高亮层技巧**：每条消息由「透明文字的 `<textarea>` + 绝对定位、`pointer-events: none` 的 backdrop」叠成，backdrop 内用 `<mark>` 着色，从而在可编辑文本框上实现实时高亮。
- **改动区间计算**：`diffSpan()` 用公共前缀 + 公共后缀找出单段改动区间，绿色底色标记的就是这一段。
- **大列表性能**：侧栏一次性拼接 `innerHTML` 并用点击事件委托；检索用的逐会话小写文本 `state.searchText` 惰性构建；消息文本框用 `scrollHeight` 自适应高度。
- **安全性**：所有插入 HTML 的文本都经过 `escapeHTML()`；搜索词构造正则前用 `escapeRegExp()` 转义。

## 已知限制与注意事项

- **刷新会丢失未导出的编辑**：`restoreEdits()` 未接入启动流程，加载文件时还会主动清除该文件的暂存；请养成随时导出的习惯。
- **顶栏「撤销」按钮未生效**：目前唯一可用的撤销是批量替换区的「↶ 撤销上一批」，且只支持回退一层。
- **批量替换作用于整份文件**，无法只针对当前会话；且区分大小写、不能替换为空串。
- **补丁文件不含会话下标**：`patch_audit` / `patch_raw` 只保存被改动会话的完整内容，回填原文件时需要自行按内容定位（详见「仓库结构与产物用途」）。
- **全部数据常驻内存**：几万条会话可流畅使用；十万级会话请留意浏览器内存与首屏渲染时间。
- **浏览器要求**：需支持 `Map` / 模板字符串 / `Blob` / `URL.createObjectURL` / `FileReader` 的现代浏览器（Chrome、Edge、Firefox、Safari 近期版本均可）。数据文件必须是 UTF-8 编码，否则中文会乱码。
- 页面通过 `alert()` 反馈错误与导出结果；若浏览器屏蔽了弹窗，相关提示将不可见（标注人输入已改为内嵌弹窗，不受影响）。

## 常见问题

**Q：点击「打开数据文件」没反应？**
检查是否被浏览器的文件选择器拦截；也可以直接把 JSON 拖进浏览器窗口，先确认它是不是合法 JSON。

**Q：`?data=xxx.json` 自动加载失败？**
`file://` 下 `fetch` 会被安全策略拦截，请用 `python -m http.server` 启动静态服务后通过 `http://localhost:8000/pair_annotator.html?data=xxx.json` 访问。

**Q：提示「文件不是合法 JSON」？**
文件可能带 BOM、编码不是 UTF-8，或实际是 JSON Lines。先转成标准 UTF-8 JSON 数组。

**Q：提示「数据结构校验未通过」？**
按提示修正：首条必须是 `system`、只能有一条 `system`、`user`/`assistant` 必须交替且成对。弹窗只展示前 10 条，修正后重新加载即可看到剩余问题。

**Q：改完的内容去哪了？**
点任一导出按钮下载。浏览器关掉后，未导出的修改不会自动恢复。

**Q：多人同时标注同一份数据？**
每人各自导出（文件名自带标注人），先用 `data_sig` 确认大家基于同一份原始文件；同一会话被多人改过时，比对 `patch_audit` 里的 `annotator` / `exported_at` 后人工裁定，或各自交付 `full_*` 完整文件再按人合并
